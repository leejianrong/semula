# AGENTS.md

## What

semula is a mock LLM server powered by your AI subscription: an OpenAI-compatible endpoint where a coding agent (Claude Code, Codex) answers over MCP or CLI instead of a paid API. Answers are recorded and replayed; in record mode unknown prompts park for the agent. Python 3.11+, FastAPI, SQLite, `uv`. src layout in `src/semula/`.

Status: 0.4.0 released (2026-10-27, tag v0.4.0; 0.3.0 on 2026-10-25, 0.2.0 on 2026-10-23, 0.1.0 on 2026-10-22): image on ghcr.io, CLI binaries, docs site at leejianrong.github.io/semula. Built: record/replay, record-through to a real provider behind a call and token cap with a dry run (ADR-0013), a miss ceiling per run (`max_misses`), answer skeletons and a conversation view on parked calls, `claim_next` with a lease, the answerer hook that runs the operator's command per parked call (ADR-0014: off by default, never for hosted tenants; 0.4.0, epic E16 for the Wavelength team), streaming and tools, projects and entries, tiered matching with review, MCP/CLI/API key, observability, export/import, embeddings, SQLite and Postgres, mode per project, the whole dashboard (log, pending, entries, editor, review, playground), and hosted semula (ADR-0010 and 0011: sign-in with OIDC/GitHub, roles, scoped API tokens, audit, quotas, tenancy with Postgres RLS, replicas, workspace deletion) with its dashboard behind sign-in and admin screens (ADR-0012: stays on indah). Hosted needs the `hosted` and `postgres` extras, so the published image is local-only. See the Pandan board for live status. Trust the code over any doc where they disagree, and fix the doc.

## Why

Cut LLM API cost in dev and test by turning a coding-agent subscription into an LLM API endpoint. Recording and matching are supporting features; the subscription-powered endpoint is the main selling point, so lead with it in docs and README. The load-bearing choices are in `docs/adr/` (read 0002 on the record queue, 0003 on matching, 0013 on record-through and 0014 on the answerer hook (it runs a command) before touching those areas). Decisions and their status: `docs/QUESTIONS.md`. Plan: `docs/PLAN.md`.

## How

- Setup: `uv sync --extra dev` (or `make setup`), then `make hooks` once.
- Gate before pushing: `make check` (ruff, mypy strict, fast tests). `make help` lists everything.
- Fast layer = tests marked `unit` or `integration`: no network, no Docker, temp SQLite only. `e2e` boots the real container and runs in CI only. Never let a slow test into the fast layer. `browser` (`make test-browser`) drives the real dashboard in Chromium, Firefox and WebKit (stored text never runs; phone width and keyboard use) and runs as its own CI job; WebKit cannot start on many laptops, so it skips there but must pass in CI. `perf` (`make bench`) holds the replay latency budget, `make image-check` the image budgets (Docker), and `embeddings` (`make test-embeddings`) the real model; each runs as its own CI job. Embedding code stays in `embeddings.py` and imports numpy and fastembed lazily, so the default install never loads them.
- Docs site: `docs/` is built with Zensical (`zensical.toml`; `make docs` fails on any warning, `make docs-serve` previews). The tutorial, guide and reference are the user docs; planning notes (`PLAN`, `SLICES`, `QUESTIONS`, `INDAH-*`, `design/`), the ADRs (`adr/`) and `RELEASING.md` are excluded from the site. Change a command, flag, MCP tool, route or setting and update `docs/reference/` in the same PR: `tests/unit/test_docs_reference.py` fails when the tables drift. Every code block in the tutorial was run against a container; keep it that way.
- Work is tracked on Pandan board **SEM** (board 39, use the `pandan` skill). Pick a card, branch per slice off fresh `main`, land via PR with green CI. No direct pushes to `main`: GitHub does not block the owner, so `make hooks` is what does (the hook refuses a push to main). Create the branch as its own step and push it by name (`git push -u origin <branch>`, never `HEAD`).
- Every bug or flake gets a failing test first, then the fix.
- All surfaces (REST, CLI, MCP, dashboard) call one service layer; never write the database from a surface (ADR-0005).
- Database: SQLAlchemy Core + Alembic, SQLite locally and Postgres hosted (ADR-0009). Change `schema.py` and add an Alembic revision together (a test fails if they drift); no raw SQL in the service; keep handlers non-blocking. `make test-postgres` runs everything on Postgres (needs Docker).
- Tenancy (ADR-0011): the service is bound to a workspace with `for_scope`; every query filters by `self.workspace_id`. Add a public `Service` method and list it in `tests/integration/test_tenant_isolation.py` (a scenario calling it as another workspace, or an exemption with a reason), or the suite fails.
- Add a runtime dependency only in the slice that first needs it, and check its licence and offline behaviour.
- Never commit secrets, `.env`, or a `data/` directory. Recorded prompts can contain secrets, so never put real recordings in fixtures.
- The dashboard is built on indah (`/home/jian/projects/abang-ai/indah`) after the headless core. Needs for indah go in `docs/INDAH-REQUESTS-PROMPT.md`; do not file indah cards without asking.
